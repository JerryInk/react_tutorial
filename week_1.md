## 1. Теоретический блок (25 минут)
## Библиотека против фреймворка
В отличие от Angular, который является жестким каркасом («всё из коробки»), React — это исключительно библиотека для построения пользовательских интерфейсов (View-слой).

* Angular диктует архитектуру, встроенный HTTP-клиент, роутер и формы.
* React дает полную свободу. Вы сами выбираете инструменты для роутинга или запросов, собирая стек под конкретную задачу.

## Декларативность против императивности
React работает по декларативному принципу. Вместо написания пошаговых инструкций по изменению DOM (императивный подход), вы просто описываете интерфейс для каждого конкретного состояния данных. Когда данные меняются, React сам перерисовывает нужные участки экрана.
## Как работает Virtual DOM
Прямое обновление реального DOM в браузере — самая «дорогая» операция для производительности. React решает это через виртуальную копию:

   1. При изменении данных создается новый Virtual DOM (легковесный JS-объект).
   2. React сравнивает его со старым Virtual DOM (процесс Reconciliation / Алгоритм Diffing).
   3. Находится минимальная разница, и React точечно обновляет только изменившиеся узлы в реальном DOM.

## Инструментарий: Почему Vite?
Раньше стандартом был Create React App (CRA) на базе Webpack. Сегодня он официально устарел. Мы используем Vite — современный инструмент сборки. Он не пересобирает весь проект при каждом изменении, а использует нативные ESM-модули браузера, обеспечивая мгновенный запуск и горячую перезагрузку (HMR).
## Что такое JSX
JSX (JavaScript XML) — это расширение синтаксиса JavaScript, позволяющее писать HTML-подобную разметку прямо внутри кода.

* Браузеры не понимают JSX. На этапе сборки компилятор (Babel или SWC) превращает теги в обычные вызовы функций ```React.createElement()```, ```_jsx('h1', { children: 'Привет' })``` или аналогичные внутренние методы пакета react/jsx-runtime.

Основные правила JSX:

* Один корень: Компонент должен возвращать ровно один родительский элемент. Если обертка в DOM не нужна, используют фрагмент: ```<></>```.
* CamelCase для атрибутов: Вместо class пишем ```className```, вместо onclick — ```onClick```.
* JS-выражения: Любой JS-код (переменные, условия, методы массивов) пишется внутри фигурных скобок ```{ }```.

## 2. Практический блок (15 минут)
## Шаг 1. Развертывание проекта
Создаем проект с помощью Vite, выбирая пресет React и чистый JavaScript (или TypeScript, по желанию):
```bash
npm create vite@latest react-lecture-1 -- --template react
cd react-lecture-1
npm install
npm run dev
```
## Шаг 2. Разбор точки входа
Открываем файл ```src/main.jsx```. Здесь происходит инициализация приложения в React 18+:
```jsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import './index.css'
import App from './App.jsx'

// Находим реальный узел в index.html и создаем виртуальный корень React
createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
```
## Шаг 3. Создание первого JSX-компонента
Заменим содержимое файла ```src/App.jsx``` на базовый декларативный компонент:
```jsx
function App() {
  const username = "Алексей";
  const isLoggedIn = true;
  const pageTitle = "Добро пожаловать в мир React";

  return (
    <div className="container">
      {/* 1. Вывод переменной в JSX */}
      <h1>{pageTitle}</h1>
      
      {/* 2. Условный рендеринг */}
      {isLoggedIn ? (
        <p>Привет, {username}! Рады тебя видеть.</p>
      ) : (
        <p>Пожалуйста, войдите в систему.</p>
      )}

      {/* 3. Использование фрагмента, если нужно вернуть соседние элементы */}
      <>
        <hr />
        <footer>Курс по React, 2026.</footer>
      </>
    </div>
  );
}

export default App;
```

## 3. Чек-лист для самопроверки (3 минуты)

* Понимаете, почему React называют библиотекой, а Angular — фреймворком.
* Можете объяснить разницу между реальным DOM и Virtual DOM.
* Помните, какой атрибут в JSX используется вместо стандартного class.
* Знаете, зачем нужен ```<React.StrictMode>``` в режиме разработки.
